CORE CONCEPTS

Display and visibility

The display, visibility, and overflow properties answer different questions: how an element participates in layout, whether it is painted, and how content exceeding a box is handled.

01

Block

A block-level box normally starts on a new line and can participate in width and height calculations.

display: block;
02

Inline

An inline box participates in the current line flow. Width and height do not behave like they do on a normal block.

display: inline;
03

Inline-block

An inline-block participates in line flow while behaving like a rectangular box for sizing.

display: inline-block;
04

None

The element is removed from the layout as if the element were not participating in the box tree for rendering.

display: none;
05

Visibility

visibility: hidden hides the element while preserving its layout space.

visibility: hidden;
06

Overflow

Overflow controls what happens when content does not fit inside the element's box.

overflow: auto;

POSITIONING

Five positioning modes

Positioning changes how an element is placed relative to normal flow, an ancestor, or the viewport.

static

The normal positioning mode. The element participates in ordinary document flow and offset properties do not reposition it.

relative

The element remains in normal flow, but its visual position can be shifted with offsets such as top and left.

absolute

The element is removed from normal flow and positioned relative to an appropriate positioned containing block.

fixed

The element is taken out of normal flow and normally positioned relative to the viewport.

sticky

The element behaves like a relatively positioned element until a scrolling threshold causes it to stick within its container.

sticky demonstration

Scroll the page and observe the sticky label. Its behavior depends on its scrolling container and offset threshold.

Positioning is separate from display. An element can be block, inline-block, flex, grid, or another display type while also having a positioning mode.

REFERENCE

Behavior at a glance

Property Primary question Layout space preserved? Typical use
display: block How does the box participate in flow? Yes Sections, containers, paragraphs
display: inline Should the box participate in line flow? Yes Text-level content
display: inline-block Should it be inline but size like a box? Yes Buttons, badges, compact controls
display: none Should it participate in rendering layout? No Conditional UI
visibility: hidden Should the box be painted? Yes Hiding while retaining layout space
overflow: auto What happens when content exceeds the box? Yes Scrollable panels

Accessibility note

Visual hiding and semantic availability are different concerns. Choose a technique according to whether content should remain in layout, remain exposed to assistive technologies, or disappear from the rendered interface entirely.
